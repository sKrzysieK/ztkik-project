\section{Results}\label{sec:results}

\subsection{Classification Quality}

\Cref{tab:metrics} compares the encrypted classifier with the baselines on the \num{1035} test messages.
The encrypted classifier reaches an accuracy of \SI{98.07}{\percent}, above the \SI{94}{\percent} target and \num{10.7} percentage points above the majority-class baseline, which never detects spam.
All of its metrics are identical to those of the plaintext model, including ROC-AUC: the decrypted scores order the messages exactly as the floating-point scores do.
Logistic regression on the same features performs on par (F1 of $0.920$ versus $0.922$), so naive Bayes costs nothing in quality compared with this stronger linear model.
The ROC curves in \cref{fig:roc} of the encrypted and plaintext classifiers coincide.

\subsection{Agreement and Quantization Error}

Both agreement criteria of \cref{sec:threat-model} are met.
The encrypted classifier assigns the same label as the plaintext model to all \num{1035} test messages, and for every message the decrypted integer $\tilde{\Delta}$ is equal to the same fixed-point computation done in plaintext, so the homomorphic evaluation introduces no error at all.

The only difference from the floating-point classifier is the rounding to multiples of $1/S$.
Over the test set, $|\tilde{\Delta}/S^2 - \Delta|$ is at most \num{1.35e-5} and \num{1.5e-6} on average, below the bound of \num{5e-5} derived in \cref{sec:fixed-point}.
The message closest to the decision boundary has $|\Delta| = 0.031$, more than \num{2000} times the largest error, so no prediction changes sign; the scale $S = 10^6$ leaves a wide margin.

\subsection{Performance}

\Cref{tab:cost} lists the cost per message on a single core.
Client-side encryption dominates: it takes $k$ full encryptions, about \SI{4}{\milli\second} each for a \num{2048}-bit key, so encrypting a message with $k = 1000$ takes \SI{4.0}{\second}.
The server needs only $k$ exponentiations with exponents of at most 23~bits, which is over 50~times cheaper, and the client decrypts a single ciphertext in about \SI{1}{\milli\second}.
All costs grow linearly with $k$; a \num{3072}-bit key makes encryption three times slower than a \num{2048}-bit one.
Each feature is sent as a ciphertext of $2|n|$~bits, i.e.\ \SI{512}{\kilo\byte} per message for $k = 1000$ and a \num{2048}-bit key.
The full test set (\num{1035} messages, \num{2048}-bit key) takes \SI{608}{\second} with encryption spread over 15 processes: \SI{539}{\second} for encryption, \SI{68}{\second} for the server and \SI{1.2}{\second} for decryption, i.e.\ about \SI{0.6}{\second} per message; repeated runs on the same machine took between \num{608} and \SI{668}{\second}.

\Cref{fig:accuracy-vs-k} shows the trade-off behind the choice of $k$.
Accuracy alone changes little (from $0.935$ at $k = 100$ to $0.980$ at $k = 1000$), but the F1 score of the spam class rises from $0.66$ at $k = 100$ and $0.75$ at $k = 200$ to $0.89$ at $k = 500$ and $0.91$ at $k \ge 750$.
Going from $k = 750$ to $k = 1000$ adds a third to the cost for a gain of only \num{0.3} percentage points of F1; cross-validation selects $k = 1000$, and at \SI{0.6}{\second} per message in parallel this cost is acceptable for our setting.
