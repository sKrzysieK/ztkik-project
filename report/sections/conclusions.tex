\section{Conclusions}\label{sec:conclusions}

A multinomial naive Bayes spam filter can classify SMS messages encrypted with the Paillier cryptosystem without any loss of quality.
All three success criteria of \cref{sec:threat-model} are met.
The encrypted classifier reaches an accuracy of \SI{98.07}{\percent} on the deduplicated test set, above the \SI{94}{\percent} target.
It assigns the same label as the plaintext model to all \num{1035} test messages, and every decrypted score is equal to the same fixed-point computation done in plaintext.
Rounding to fixed point changes a score by at most \num{1.35e-5}, more than \num{2000} times less than the smallest margin on the test set, so the encrypted filter makes the same decisions as the plaintext one.

The cost lies almost entirely with the client.
Encrypting the \num{1000} features of a message with a \num{2048}-bit key takes about \SI{4}{\second} on one core and produces \SI{512}{\kilo\byte} of ciphertexts, whereas the server computes the encrypted score in about \SI{74}{\milli\second} and the client decrypts it in about \SI{1}{\milli\second}.
Encryption parallelizes well (\SI{0.6}{\second} per message on 15 processes), so the delay is acceptable for an individual user, but the bandwidth is more than three orders of magnitude larger than the message itself.

The security analysis supports the threat model: a server that learns from ciphertexts of messages it encrypted itself does no better than always predicting ham.
Attacks 2--4, however, show that this guarantee holds only for the protocol as designed.
Sending only the non-zero features, reusing the randomness $r$, or using the floating-point encoding of \texttt{phe} would reveal, respectively, which words occur in a message, all feature values, or some of the occurring words.
None of this is covered by IND-CPA, so encrypting the full vector with fresh randomness and integer encoding is a security requirement, not an implementation detail.

\textit{Limitations.}
The protocol protects only the client's messages against a passive server.
The model is public to the server, and the client learns $\Delta$ for every message, which with enough queries could let it extract the model.
A malicious server could return arbitrary scores, which the client cannot verify, and the number and timing of messages remain visible.
The approach is limited to classifiers with a linear decision function: logistic regression, which performs on par on our data (\cref{tab:metrics}), would work in the same way, but non-linear models or a model hidden from the server require interactive protocols such as those of Bost et al.~\cite{bost2015}.

\textit{Future work.}
Most of the cost of an encryption is the exponentiation ${r^n \bmod n^2}$, which does not depend on the message.
The client could therefore precompute these values in advance and reduce online encryption to one modular multiplication per feature, which would remove most of the client's delay; the bandwidth would remain the main cost.
